### جریان OTP (کارمندِ بدون رمز)

وقتی مدیر کارمند را **بدون رمز اولیه** بسازد، آن کارمند با کد یکبارمصرف رمز می‌سازد:

1. در صفحه ورود وب → «ثبت‌نام با کد یکبارمصرف»
2. وارد کردن شماره → «دریافت کد تأیید»
3. چون provider فعلی `mock` است، کد در **لاگ ترمینال بک‌اند** چاپ می‌شود:
   ```
   [otp:mock] code for 09XXXXXXXXX: 123456
   ```
4. کد ۶ رقمی را در فرم وارد کنید → ساخت رمز جدید (حداقل ۸ کاراکتر) → ورود خودکار

اعتبار کد: ۵ دقیقه؛ حداکثر ۵ تلاش اشتباه.

## ۳) برنامه تست دستی وب

### الف) مدیر سیستم (System Admin)

وب فقط برای کاربران شرکت است؛ عملیات مدیر سیستم از API انجام می‌شود:

| # | اقدام | نتیجه مورد انتظار |
|---|---|---|
| A1 | ارسال `POST /api/v1/auth/admin/login` با `{"username":"admin","password":"admin1234"` | کد 200 + توکن |
| A2 | `POST /api/v1/admin/companies` با `{name, manager:{firstName,lastName,mobile,password}}` | 200 + پیام «شرکت و مدیر آن ساخته شد» |
| A3 | ورود مدیر تازه‌ساخته از صفحه `/login` وب | ورود موفق و نمایش داشبورد مدیر |

(مثال A2:)
```bash
curl -X POST http://127.0.0.1:3001/api/v1/admin/companies \
  -H "Authorization: Bearer <توکن A1>" -H "Content-Type: application/json" \
  -d '{"name":"شرکت آزمون","manager":{"firstName":"تست","lastName":"مدیر","mobile":"09180000001","password":"Test!2345"}}'
```

### ب) مدیر شرکت

| # | اقدام (صفحه) | نتیجه مورد انتظار |
|---|---|---|
| B1 | ورود با `09120000001 / manager1234` در `/login` | هدایت به داشبورد با ۶ کارت آماری پرشده |
| B2 | مشاهده داشبورد | کارت‌ها: کل پرونده‌ها/باز/در حال انجام/انتظار پذیرش/عقب‌افتاده/کارکنان فعال + بخش‌های فوری، نمودار وضعیت، افراد در حال کار، فعالیت‌های اخیر |
| B3 | «کارکنان» ← «افزودن کارمند» با شماره جدید بدون رمز | پیام «کارمند ساخته شد…» + ردیف جدید با برچسب «رمز تعیین نشده» |
| B4 | همان کارمند ← دکمه «تعلیق» | وضعیت به «غیرفعال» تغییر کند |
| B5 | همان کارمند ← «فعال‌سازی» | بازگشت به «فعال» |
| B6 | «بازنشانی رمز» با رمز ≥۸ کاراکتر | پیام «رمز … بازنشانی شد» |
| B7 | «پرونده‌ها» ← «＋ پرونده جدید» ← عنوان + اولویت «زیاد» + انتخاب نفر در بخش ارجاع | پیام «پرونده ساخته شد»؛ پرونده جدید در لیست با وضعیت «در انتظار پذیرش» |
| B8 | کلیک روی پرونده | صفحه جزئیات با خط زمان، گردش ارجاع، دکمه‌های ثبت نتیجه/انتقال/یادآوری/پیوست |

### ج) کارمند

| # | اقدام | نتیجه مورد انتظار |
|---|---|---|
| C1 | ورود با `09120000002 / employee1234` | داشبورد کارمند با کارت‌های «کارهای من» و… ؛ منوی کناری متفاوت از مدیر (بدون گزارش/کارکنان) |
| C2 | «ارجاع‌های جدید» | کارت پرونده ارجاع‌شده با دکمه‌های پذیرش/رد کردن |
| C3 | «✓ پذیرش کار» | پیام «پرونده پذیرفته شد»؛ وضعیت پرونده → «در حال انجام» |
| C4 | سناریوی رد: ابتدا یک ارجاع دیگر بسازید سپس «✕ رد کردن» بدون دلیل | دکمه ثبت غیرفعال (حداقل ۳ کاراکتر لازم) |
| C5 | رد با نوشتن دلیل | پیام «پرونده رد شد»؛ پرونده به ارجاع‌دهنده بازمی‌گردد و در تاریخچه ردیف «بازگشت (رد)» با دلیل دیده می‌شود |
| C6 | جزئیات پرونده متعلق ← «▶ شروع کار» | پیام «کار شروع شد» + دکمه تبدیل به «⏹ پایان کار»؛ در داشبورد کارت «کار فعال» زیاد می‌شود |
| C7 | «⏹ پایان کار» | نمایش مدت محاسبه‌شده در خط زمان |
| C8 | «📝 ثبت نتیجه» + تیک تکمیل | پیام «پرونده تکمیل شد»؛ وضعیت → «تکمیل شده»؛ باکس سبز نتیجه در بالای صفحه |
| C9 | «📤 انتقال به همکار» + انتخاب فرد | «پرونده ارجاع شد»؛ وضعیت → «در انتظار پذیرش» تا پذیرش گیرنده |
| C10 | «⏰ یادآوری» با تاریخ/ساعت آینده | «یادآوری ساخته شد»؛ ردیف در صفحه «یادآوری‌ها» ظاهر می‌شود |
| C11 | در صفحه یادآوری‌ها ← «انجام شد + ثبت نتیجه» | یادآوری از حالت فعال خارج و نتیجه روی پرونده درج می‌شود |

### حالت‌های عمومی UI
- **خالی:** مثلاً «ارجاع‌های جدید» بدون ارجاع → EmptyState با آیکون.
- **خطا:** خاموش کردن API و رفرش → ErrorState با دکمه «تلاش دوباره».
- **موبایل:** عرض کمتر از lg → هدر با دکمه ☰ و کشوی کناری.

- ایمولاتور بدون اجرای API روی میزبان: timeout 20 ثانیه‌ای.

## ۵) سناریوی پذیرش کامل کسب‌وکار (تست یک‌بار)

**پیش‌نیاز:** ترمینال‌های ۱ تا ۳ بالا در حال اجرا.

1. **ورود مدیر** (`09120000001`) → داشبورد.
2. **ساخت پرونده** «تمدید قرارداد مشتری آلفا»، اولویت زیاد، ارجاع به آرمان (`09120000002`).
   - *انتظار:* پرونده = «در انتظار پذیرش»، مسئول = خالی، اعلان برای آرمان ثبت شود.
   - *دیتابیس:* ردیف `case_assignments` با reason=`INITIAL_ASSIGNMENT`, status=`PENDING`.
3. **آرمان** لاگین → «ارجاع‌های جدید» → **پذیرش**.
   - *انتظار:* پرونده = «در حال انجام»، مسئول = آرمان.
4. آرمان **شروع کار** → چند لحظه صبر → **پایان کار**.
   - *انتظار:* ردیف `work_sessions` با durationSeconds>0؛ دو رویداد START_WORK/END_WORK در خط زمان.
5. آرمان **انتقال** به علی (`09120000003`) با توضیح.
   - *انتظار:* پرونده = «در انتظار پذیرش» و مسئول خالی (هیچ‌کس مالک نیست تا پذیرش).
6. **علی** لاگین → پذیرش.
   - *انتظار:* مسئول = علی، پرونده = «در حال انجام».
7. علی **یادآوری** برای ۱۰ دقیقه بعد.
   - *انتظار:* ردیف reminders با status=`ACTIVE`؛ پس از سررسید، اعلان REMINDER_DUE (با بازدید صفحه یادآوری/داشبورد).
8. علی **ثبت نتیجه** با تیک تکمیل: «تمدید انجام شد…».
   - *انتظار:* پرونده = «تکمیل شده»؛ result و resultAt پر شوند.
9. **بررسی تاریخچه:** مدیر صفحه پرونده را باز کند.
   - *انتظار:* گردش ارجاع شامل `ارجاع اولیه → انتقال` (به‌ترتیب)، بدون هیچ امکان حذف/ویرایش؛ خط زمان کامل CREATE→ASSIGN→ACCEPT→START_WORK→END_WORK→ASSIGN→ACCEPT→RESULT_ADDED→COMPLETE (+REMINDER_CREATED).
10. **داشبورد مدیر:** کارت «کل پرونده‌ها» و «تکمیل‌شده» افزایش یافته؛ گزارش کارکنان زمان کار آرمان را نشان می‌دهد.

**قانون طلایی:** هیچ‌جای سیستم دکمه حذف/ویرایش برای ارجاع‌ها و فعالیت‌ها وجود ندارد — این عدم وجود، خودِ تست immutability است.

## ۶) عیب‌یابی

| مشکل | علت رایج | راه‌حل |
|---|---|---|
| API بالا نمی‌آید (`EADDRINUSE`) | نمونه قبلی روی 3001 مانده | `netstat -ano \| findstr :3001` سپس `taskkill /PID <pid> /F` |
| `Can't reach database server at 127.0.0.1:5433` | داکر خاموش | Docker Desktop را اجرا کنید، بعد `docker compose up -d` و صبر تا healthy |
| داکر start نمی‌شود | WSL/مجازی‌سازی | Docker Desktop را یک‌بار از GUI باز کنید (احتمالاً دیالوگ خطا/آپدیت منتظر شماست) و دوباره امتحان کنید |
| وب باز نمی‌شود / خطای شبکه در صفحات | API خاموش یا پورت اشتباه | سلامت API را با curl بررسی کنید؛ پروکسی وب پیش‌فرض به `127.0.0.1:3001` است |
| تاریخ‌ها/اعداد لاتین‌اند | فونت/کش | مطمئن شوید CSS وب لود شده (Ctrl+F5)؛ اعداد باید فارسی باشند |
| APK وصل نمی‌شود (ایمولاتور) | API روی میزبان اجرا نیست | ترمینال ۲ را روشن کنید؛ `10.0.2.2` فقط از داخل ایمولاتور معتبر است |
| APK وصل نمی‌شود (گوشی واقعی) | IP/فایروال | `--dart-define=FOLLOWA_API=http://<LAN-IP>:3001/api/v1` و باز بودن 3001 در فایروال ویندوز |
| build موبایل خطای loopback/Gradle | فضای TEMP دارای فاصله / JDK | `TEMP=TMP=C:\grtmp` و `JAVA_HOME=...\jdk-17.0.20.8-hotspot` |
| کد OTP نمی‌دانم | provider=mock | کد در ترمینال بک‌اند: `[otp:mock] code for …` |
