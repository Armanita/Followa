# Followa Product Specification --- Version 1.0

## 1. Product Vision

Followa یک سیستم مدیریت پیگیری و گردش کار داخلی شرکت است.

هدف اصلی:

-   جلوگیری از فراموش شدن پیگیری‌ها
-   مشخص بودن مسئول هر موضوع در هر لحظه
-   حفظ کامل تاریخچه گردش کار
-   ایجاد دید مدیریتی روی فعالیت کارکنان
-   ثبت نتیجه واقعی هر پیگیری

Followa یک سیستم Task ساده نیست؛ هسته سیستم بر اساس Case (پرونده/موضوع
پیگیری) طراحی می‌شود.

------------------------------------------------------------------------

# 2. Product Scope

نسخه MVP:

-   یک شرکت
-   حدود ۳۰ کاربر
-   زبان فارسی
-   رابط کاربری RTL
-   تقویم شمسی
-   Web + Android
-   تمرکز اصلی روی استفاده موبایل کارکنان

هدف MVP: یک سیستم عملیاتی قابل استفاده، نه یک پلتفرم Enterprise پیچیده.

------------------------------------------------------------------------

# 3. User Roles

## 3.1 System Admin

بالاترین سطح دسترسی سیستم.

وظایف:

-   ایجاد شرکت
-   ایجاد اولین مدیر شرکت
-   تنظیمات سیستم
-   مدیریت تنظیمات API

محدودیت:

System Admin به عملیات روزانه شرکت دسترسی ندارد.

عدم دسترسی:

-   پرونده‌های شرکت
-   فعالیت کارکنان
-   گزارش‌های عملیاتی شرکت

------------------------------------------------------------------------

## 3.2 Company Manager

مدیر شرکت.

دسترسی‌ها:

-   مشاهده تمام پرونده‌های شرکت
-   ایجاد پرونده
-   ارجاع پرونده
-   مشاهده گزارش‌ها
-   مدیریت کارکنان
-   فعال/غیرفعال کردن کارکنان

------------------------------------------------------------------------

## 3.3 Employee

کارمند شرکت.

دسترسی‌ها:

-   ورود به سیستم
-   ایجاد پرونده
-   انجام پرونده‌های مرتبط با خودش
-   ثبت نتیجه
-   ثبت فایل و صوت
-   ایجاد یادآوری
-   ارجاع پرونده به فرد دیگر

------------------------------------------------------------------------

# 7. Core Concept: Case

واحد اصلی سیستم Case است.

مثال:

موضوع:

تماس با مشتری X

مراحل:

1.  تماس انجام شد
2.  مشتری درخواست پیش‌فاکتور کرد
3.  فایل proposal.pdf اضافه شد
4.  مرحله بعد: ارسال قیمت فردا

پرونده زمانی تمام می‌شود که موضوع کاملاً بسته شده باشد.

------------------------------------------------------------------------

# 8. Case Lifecycle

یک Case می‌تواند:

-   توسط مدیر ساخته شود
-   توسط کارمند ساخته شود
-   بین افراد مختلف منتقل شود

نمونه گردش:

    Manager
       |
       v
    Arman
       |
       v
    Ali
       |
       v
    Mahsa
       |
       v
    Arman
       |
       v
    Completed

همچنین ممکن است:

    Manager
       |
       v
    Employee
       |
       v
    Completed

یعنی ارجاع همیشه الزامی نیست.

------------------------------------------------------------------------

# 9. Assignment Rules

هر لحظه فقط یک مسئول فعال وجود دارد.

هر انتقال باید ثبت شود:

-   ارسال کننده
-   دریافت کننده
-   دلیل
-   توضیح

دریافت کننده دو انتخاب دارد:

## Accept

قبول انجام کار.

## Reject

نمی‌توانم انجام دهم.

اجباری:

-   دلیل رد کردن

بعد از Reject:

پرونده به ارجاع‌دهنده برمی‌گردد.

------------------------------------------------------------------------

# 10. Assignment History

تاریخچه هیچ وقت حذف نمی‌شود.

کاربری که قبلاً پرونده را ارجاع داده:

می‌تواند:

-   تاریخچه را ببیند

ولی:

-   حق ویرایش ندارد
-   حق تغییر ندارد

مگر اینکه دوباره پرونده به او ارجاع شود.

------------------------------------------------------------------------

# 11. Employee Visibility

کارمند فقط می‌بیند:

-   پرونده‌های فعلی خودش
-   پرونده‌هایی که ساخته
-   تاریخچه ارجاع‌هایی که خودش در آن بوده

نمی‌بیند:

-   پرونده سایر کارکنان
-   اطلاعات داخلی سایر گردش‌ها

------------------------------------------------------------------------

# 12. Manager Visibility

-   تمام پرونده‌های شرکت

را مشاهده می‌کند.

------------------------------------------------------------------------

# 13. Reminder System

هدف:

هیچ پیگیری فراموش نشود.

کاربر هنگام ثبت پیگیری:

-   تاریخ
-   ساعت

را تعیین می‌کند.

امکان:

-   یادآوری قبل از زمان
-   یادآوری در زمان مقرر

وجود دارد.

پس از انجام:

کاربر:

-   نتیجه را ثبت می‌کند
-   در صورت نیاز یادآوری جدید ایجاد می‌کند

------------------------------------------------------------------------
